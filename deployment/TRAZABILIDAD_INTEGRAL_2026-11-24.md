El despliegue usó el digest de la imagen validada y conservó la configuración de ejecución de producción. - La revisión privada viora-audit-qa-00004-66r pasó la suite autenticada con datos de viora_audit_qa. Después del cambio de revisión se consultaron los eventos creados previamente. Cloud Logging confirmó doce consultas concurrentes respondidas con HTTP 200 desde dos instancias, con ocho y cuatro respuestas respectivamente.
- La revisión de producción viora-00031-fit quedó activa con el 100 % del tráfico. En la URL pública respondieron la salud y el inicio de sesión con HTTP 200. Auditoría redirigió al inicio de sesión con HTTP 302 y la trazabilidad individual rechazó el acceso anónimo con HTTP 401. La validación autenticada se ejecutó en QA. [VIORA en producción](https://viora-1055595302579.us-central1.run.app)
- En producción se verificaron 68 eventos después de promover la revisión. Los primeros 64 coincidieron con el punto de control archivado antes del despliegue. La segunda comprobación quedó guardada en LOCALAPPDATA/VIORA/Integridad/viora_production-2026-11-24-viora-00031-fit.json.
- PayPal Sandbox respondió HTTP 200 para consultar el webhook existente y confirmó ocho tipos registrados, incluidos activación, suspensión, vencimiento, cancelación, cobro completado, fallo, reversión y reembolso. Las pruebas de esta intervención usaron datos aislados y consultas de proveedor de solo lectura.
